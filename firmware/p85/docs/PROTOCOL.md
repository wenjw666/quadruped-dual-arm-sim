# P85 CAN FD 与 A/R 业务协议

## 资料依据与未决事项

以下 CAN 字段来自用户提供的《P85MAX-S关节电机协议手册-v1.0.pdf》（CANFD 版）；物理参数来自《P85MAX-S外形图和性能参数-V4-20260305.pdf》。A/R 应用协议为本工程自行定义，不属于电机协议。

原始资料目录：`D:/1110实验课任务划分/1110实验课任务划分/canfd通信位置跟踪/`。完整协议实现见 `src/p85_protocol.c`，接口见 `include/p85_protocol.h`。

厂家同时给出端点线性映射和“0x8000 表示零”。本实现保留端点映射，四舍五入；对称量程的精确零单独编码/解码为 `0x8000`。零附近存在一个量化台阶，实机需结合厂商参考代码或抓包确认。协议文档没有完整定义断流后的驱动器动作、MSGID 回绕语义或多电机应答时序，不自行补充为硬件保证。

## CAN 命令

标准 11 位仲裁 ID，主机 ID `0x000`；电机 ID 1–6，默认 3。仲裁段 1 Mbps，数据段 5 Mbps，CAN FD + BRS。DLC 对应 64 字节，非 8 字节 MIT 混合位宽帧。

| 字节 | 内容 |
| --- | --- |
| 0–1 | MSGID，uint16，小端；反馈原样回传 |
| `2+10*(id-1)` 起的 10 字节 | 该 ID 电机的槽位 |
| 62–63 | 保留，初始化为零 |

默认 ID3 槽位是字节 22–31。每个运行槽由以下 5 个小端 uint16 组成：

| 槽内偏移 | 物理量 | 可编码范围 |
| --- | --- | --- |
| 0–1 | 输出端位置 | -12.5 至 +12.5 rad |
| 2–3 | 输出端速度 | -65 至 +65 rad/s |
| 4–5 | Kp | 0–500 |
| 6–7 | Kd | 0–50 |
| 8–9 | 前馈力矩 | -200 至 +200 Nm |

量程是通信编码范围，不是允许运动范围。非有限数和越界值被拒绝，不静默截断。运行帧前馈力矩固定为零；PD 力矩估算、反馈力矩和速度均接受独立软件检查。

特殊槽位前 9 字节全部 `FF`，最后一字节：`FC` 使能、`FD` 失能、`EF` 写机械零位。本工程 CLI 不提供机械零位写入；轨迹中心是软件中心。每次初始化完整帧，所有非目标槽位均为失能，绝不能用全零槽位表示“零位置、零速度”。

## CAN 反馈

只接受所配置电机仲裁 ID 的标准 FD 帧，长度必须为 12 字节。

| 字节 | 内容 |
| --- | --- |
| 0–1 | 被回传的 MSGID，uint16 LE |
| 2–3 | 位置，uint16，沿用运行字段量程 |
| 4–5 | 速度，uint16 |
| 6–7 | 力矩，uint16 |
| 8 | 温度，原始 uint8 减 40，单位 °C |
| 9 | 状态位 |
| 10 | 电压，uint8，1 V/LSB |
| 11 | 保留 |

状态 bit0 为使能；bit1–6 依次是过压、过流、过温、过速、编码器故障、欠压；bit7 保留。错误掩码 `0x7E`。

本控制器额外要求：MSGID 属于最近 32 条**驱动已接受**的发送记录，回传年龄不超过反馈超时，顺序比前一次成功回传新。重复、过期、重排、从未发送和错误 CAN 元数据的帧都不刷新反馈时间。驱动接受不等于报文已在总线上成功发送；实际收发和错误回调仍必须接入。

## A/R 请求帧：32 字节

全部多字节整数为小端，禁止直接传输 C 结构体。

| 偏移 | 类型 | 内容 |
| --- | --- | --- |
| 0–3 | 4 bytes | ASCII `P85C` |
| 4 | uint8 | 版本 1 |
| 5 | uint8 | 操作码 |
| 6–7 | uint16 | 会话序号 |
| 8–31 | 6 × int32 | 参数；未用参数写零 |

| 操作码 | 名称 | 参数 |
| --- | --- | --- |
| 0 | hello | 初始化空闲会话，不允许接管活动运动 |
| 1 | heartbeat | 无 |
| 2 | status | 无，同时续租 |
| 3 | config | Kp×1000，Kd×1000，速度×1e6，力矩×1000，幅度限制×1e6，最高温度整数 |
| 4 | probe | 发送失能并等待新鲜失能反馈 |
| 5 | enable | 必须已配置且探测成功 |
| 6 | hold | 运动中平滑停止并保持 |
| 7 | move | 相对使能起点的位置×1e6，时长 ms |
| 8 | sine | 幅值×1e6，周期 ms，稳定段周期数，单侧包络时长 ms |
| 9 | stop | 平滑停止并保持；不会直接失能 |
| 10 | disable | 请求失能；故障锁存不因此清除 |
| 11 | clear | 健康且新鲜的失能反馈下清除锁存故障 |
| 12 | diag | 诊断计数、温度、电压与反馈年龄 |
| 13 | demo | 位置幅值 µrad，单段时长 ms，速度幅值 µrad/s，速度正弦周期 ms，正弦周期数，整套顺序循环数 |

`demo` 由 RT0/R0 自主执行：相对使能时软件原点依次跟踪 `−A → 0 → +A → 0`，执行一周期位置正弦，再执行 `v_ref=V·sin(2πt/T)`。位置正弦使用幅值 A、周期 `2×单段位置时长` 和 `0.5×单段位置时长` 的起止包络；速度正弦的位置参考使用解析积分 `p_ref=p0+V·T/(2π)·(1−cos(2πt/T))`，每个整数周期回到 p0。每个动作在规划结束后要求速度绝对值 <0.03 rad/s、位置误差 <min(0.002, max(0.0008, 0.1×A)) rad 且连续稳定 200 ms，才推进阶段；超过规划结束 3 s 仍未稳定则触发 settle_timeout，整套动作按循环数重放后回到 HOLD。每个阶段通过状态遥测分别显示；位置、速度、力矩及周期性温度、电压、反馈新鲜度和 CAN 计数由主机打印，并将最近一次诊断值附在状态 CSV 采样中。

协议手册只定义一种力位混合运行模式。位置移动、多点位置跟踪、位置正弦和速度正弦是本工程生成的参考轨迹，不是电机固件中的不同控制模式；电机仍按同一混合控制帧执行内部力矩闭环。`demo` 在发送首帧前校验位置幅值、峰值速度、积分位移和软件行程限制；反馈跟踪超限、失联、超温/压、过流/过速或力矩限制均触发原有故障失能路径。`speed amplitude × period / π` 是速度正弦积分得到的最大位移，必须不大于配置行程。

HELLO 后按 16 位回绕递增，差值 1–32767 接受，重复或倒退拒绝；拒绝重放不会续租。32 位设备时间为单调毫秒值，差值按无符号回绕计算。有效会话内操作会续租，即使业务前置条件拒绝该操作。

MsgBox 路由：CPU0 `0x10` ↔ RT0 `0x90`，fid 0、sid 2、cmd `0x85`，METHOD 请求/REPLY 应答。SID2 是本工程选择，必须核查匹配 SDK 中无冲突。厂商消息头 len 的单位为 8 字节，32 字节设 **len=4**；单包 `idx=0,is_eof=1`。transport token 使用请求序号低 8 位，回复完整保留 token；应用层仍校验完整 16 位序号和版本。厂商 payload 类型为 `uint64_t[4]`，逐字节访问须转换指针。

## A/R 回复帧

公共头：`P85R`、版本 1、kind、请求序号。普通回复 kind=`0x80`：

| 偏移 | 类型 | 内容 |
| --- | --- | --- |
| 8–11 | 4 × uint8 | 结果、状态机状态、锁存故障、电机状态位 |
| 12–15 | uint32 | 设备单调毫秒 |
| 16–19 | int32 | 位置×1e6 rad |
| 20–23 | int32 | 速度×1e6 rad/s |
| 24–27 | int32 | 力矩×1e6 Nm |
| 28–31 | int32 | 参考位置×1e6 rad |

诊断 kind=`0x82`：偏移 8/12/16/20 分别为 uint32 的 tx_ok/rx_ok/rx_rejected/tx_failed；24 为 int16 温度，26 为 uint8 电压，27 为 uint8 新鲜标志，28 为 uint32 反馈年龄 ms。尚无反馈时年龄为 `0xFFFFFFFF`；普通遥测中初始零值不能当作有效反馈，需查新鲜标志。

状态编号与错误编号分别见 `p85_state`、`p85_error`（`include/p85_control.h`）；Python 名称表与之对应。CSV 中的 `device_ms` 为控制任务处理请求的时刻，不是独立的硬件接收时间，也不直接证明硬实时调度。
