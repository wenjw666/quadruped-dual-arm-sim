# 第二版方案审核与实施边界

审核日期：2026-10-25。基线：`v0.1.0-foundation` / `37860c1`。开发分支：`v2/decision-rl`。

依据：用户提供的《四足双臂PickPlace项目方案_RDKX5_硬件详解版.pptx》，共 27 页，包含讲稿备注。原件位于 `D:/20261019课程方案/项目方案汇报/`，只读分析，未修改原 PPT。

## 已确认的两项取舍

1. 用户确认保留 B2 + 当前 Aubo 双臂模型。PPT 的 PiPER 型号、26 自由度及 CAN 参数是硬件参考，不直接覆盖现有模型。当前软件每臂 7 个运动关节，必须使用真实关节清单，而不能硬编码为 PPT 的六轴。
2. 用户没有现成的 B2 加双臂载荷策略，确认建立并验证“动力学环境 → PPO 训练 → 策略验证 → 任务接入”流程。Go2 示例不视为 B2 的可用权重。

## 审核结论

方案可以作为 V2 实施主线，但 V1 是运动学演示平台，不能靠开关或改名称变为 RL 物理闭环。先修动力学和任务判据，再接策略。正式整机验收必须使用同版本、固定种子和失败留档，不复用 V1 的成功标签。

## 技术核验

- 已按用户要求核查并实测 B2 开源策略，优先参考 **robot_lab + rl_sar**；详见 [B2 开源核查与首次移植测试](B2_RL_REFERENCE_AUDIT.md)。存在公开 B2 权重和训练配置，但原版策略在当前双臂模型上的速度跟踪尚未通过，不能直接接管任务。
- [Unitree RL Mjlab 官方 README](https://github.com/unitreerobotics/unitree_rl_mjlab)：当前列出的模型包含 Go2、A2、As2、G1、R1、H1_2、H2，未列 B2；需要建立本项目模型、观测、执行器和任务配置，不能直接搬用示例策略。
- [上游安装说明](https://github.com/unitreerobotics/unitree_rl_mjlab/blob/main/doc/setup_en.md)：使用独立 Python 3.11 环境与 NVIDIA GPU。现有 ROS 容器 Python 3.10 / CPU Torch 不宜原地替换成训练依赖；训练应隔离部署。
- [BehaviorTree.ROS2 Humble](https://github.com/BehaviorTree/BehaviorTree.ROS2/tree/humble)：需要 BehaviorTree.CPP 4.6+。Nav2 自身的导航树不能代替整机任务树，也不能未经核查把 BT v3 插件与 v4 混载。

## 实施关卡

1. **V2-A：物理与决策基础。** 可审计的关节/质量/接触模型，真实自由基座 + PD，任务协议与守卫、仲裁、取消测试。保留 V1 默认入口，新增明确实验入口。
2. **V2-B：RL。** 先站立，再平地速度跟踪，再双臂姿态/载荷/摩擦/延迟扰动；训练记录含种子、环境和模型指纹。烟雾训练只证明采样/优化/保存链路，不代表策略达标。合格策略经独立种子验证后才接管任务。
3. **V2-C：感知操作。** 四相机、标记 PnP 与姿态有效期、双臂分区、MTC/Servo、持物/释放/视觉验收。视觉无效时停止该技能并有限重测，严格模式禁止静默回退到配置目标。
4. **V2-D：定位导航。** 真实扫描时间、LIVO 回放对照、OctoMap/AMCL/Smac，独占 TF；再开展固定场景的任务对比。
5. **V2-E：整机评估。** 同版本至少 30 轮、目标误差 2 cm、失败原因和取消/超时测试；X5 的资源指标在真实板卡测量，独立于桌面仿真。

前一关未通过时，后一关可以开发接口，但不得标记为已验证。RL、虚拟抓取、真值定位和视觉回退状态必须出现在运行记录中。
