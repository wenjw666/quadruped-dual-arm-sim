# C1200 联合调试与资源性能记录

日期：2026-10-30  
分支：`codex/c1200-yolo-smolvlm-adaptation`

## 网络现状

主机当前有线地址为 `192.168.1.101/24`，C1200 有线地址为 `192.168.1.100/24`；主机无线地址为 `10.186.150.150/24`。板端当前只有 `192.168.1.0/24` 的直连路由，所以 ROS2 调试应优先固定在有线口，不能把无线地址直接填入板端 peer。

已在主机用户级 `.wslconfig` 启用 WSL mirrored networking。WSL 已同时看到 `192.168.1.101`、无线地址和 Docker 相关接口，SSH/TCP 以及板端 UDP 报文均可到达主机。板端抓包能够看到主机向 `9410`–`9426` 发送 CycloneDDS 报文，主机也能看到板端向 `192.168.1.101` 返回报文，说明物理链路和防火墙路径已经打通。

Docker Desktop 仍然把容器放在自己的 Linux VM/bridge 网络中。其 UDP 映射会把端口发布到 loopback 的随机主机端口，不能稳定地把 CycloneDDS participant 的地址和端口宣告为 `192.168.1.101`。因此当前 ROS2 图尚未完成跨主机 topic 匹配；问题已从“网络不通”缩小为 Docker Desktop 的 DDS participant 端口/NAT 配置。新增的 `cyclonedds_c1200_nat.xml` 和 `cyclonedds_c1200_board_nat.xml` 已加入 `ManySocketsMode=none`，用于让端口集合变得可预测。下一步应在 WSL mirrored 的本地 Docker daemon 中运行仿真容器，或改用 Zenoh/domain bridge，避免继续映射数百个 UDP 端口。

## SmolVLM CPU 性能

使用板端常驻 CPU `llama-server`、同一张 MuJoCo 输出图像、`max_tokens=64`：

- 连续两次 HTTP 请求延迟为 `8978.8 ms` 和 `4157.6 ms`，平均 `6568.2 ms`。
- 双请求并发延迟为 `8.68 s` 和 `14.99 s`；当前服务使用 `--parallel 1`，请求会排队。
- 并发期间 llama-server CPU 峰值约 `665%`（约 6.7 个核心），RSS 约 `1.03 GiB`，温度最高约 `39°C`。
- 通过 ROS2 `/smolvlm/image` 和 `/smolvlm/prompt` 完成一次完整节点测试，返回 `image_seq=5`，端到端延迟 `24632.1 ms`；此时 `vlm_node` RSS 约 `80 MiB`，llama-server RSS 约 `1.03 GiB`，CPU 峰值约 `573%`。

## SmolVLM Vulkan/Mali 性能

使用 `/userdata/smolvlm/build-vulkan/bin/llama-server`、修正后的临时 ICD JSON 和 `Mali-G78AE`：

- `--list-devices` 能枚举 `Vulkan0: Mali-G78AE (12787 MiB)`。
- 冷请求延迟 `53295.0 ms`，热缓存请求为 `2937.6 ms` 和 `2944.5 ms`。
- 热请求生成速度约 `22 token/s`，服务 RSS 约 `1.0 GiB`，线程数 22。
- GPU 推理期间 CPU 峰值约 `95%`（约 1 个核心），温度最高约 `36°C`。
- 双请求并发在 `--parallel 1` 下串行，延迟约 `50.5 s` 和 `53.4 s`，说明当前 GPU 后端应作为常驻 warm service 使用，不能按每帧冷启动。

## 能力判断

板端内存余量充足，单路 SmolVLM 服务可以长期驻留；CPU 路径在单请求下可用，但并发会迅速占满多个核心，需由 ROS 节点做请求门控和丢帧。Vulkan 路径已经能使用 Mali，热缓存时明显降低 CPU 占用，但视觉 projector 冷启动仍然很慢，且当前 `parallel=1` 会让并发请求排队。建议第一阶段保留 CPU 服务作为默认可回退路径，GPU 服务作为常驻、预热后的实验路径，并把图像频率限制在单请求完成速度以内。

资源采样脚本为 `scripts/c1200_board_resource_probe.py`，ROS2 网络探针为 `scripts/ros2_lan_probe.py`。板端日志和原始 JSON 采样保存在 `/tmp/c1200_*`，可在下一轮网络通道打通后复用同一套测试。
